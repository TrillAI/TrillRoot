Directions of use

From first launch to
an informed next step.

01

Read and accept the safety notice

On first launch, review the full Terms of Use. Scroll to the end to enable the agreement checkbox. If you do not own the device or lack authorization, exit the app.

Nothing is scanned before onboarding is complete.
02

Review the permission disclosure

Trill Root explains that it needs no runtime permissions. Continue to begin a local inspection of public build fields and a fixed allowlist of system properties.

03

Let the device snapshot finish

Ten clear status updates show what is being examined. The app then displays the exact values Android reported—without treating missing data as a positive or negative verdict.

04

Read the readiness verdict

Check the explanation beneath the result. “May be possible” still requires exact-model research. “Unknown” means stop and verify; it does not mean “try an exploit.”

05

Optionally check existing root

Tap Check existing root access only if you want to ask an already-installed root manager for a read-only grant. Denying the request does not trigger another method.

06

Compare routes and prepare

Open Routes, choose the relevant documented workflow, read every warning, and complete the preparation checklist. Export a report before seeking model-specific support.

Documented paths

Routes, not
exploit roulette.

Trill Root organizes maintained workflows and their requirements. It does not execute them, download packages, or promise compatibility.

DOCUMENTED ROUTE

Magisk image patching

Patch the correct image from the exact installed firmware, then follow the device maker’s supported flashing workflow.

  • Official OEM-unlock eligibility
  • Exact matching stock firmware
  • Computer and Android platform-tools
  • Verified recovery plan and complete backup
Stop-and-check

Never use another device’s patched image. Do not guess the target partition from Android version, and never relock with modified images installed.

Frequently asked

Important answers,
up front.

Will Trill Root root my phone automatically?+

No. It is a readiness assistant. It identifies relevant device signals, compares documented routes, and helps you prepare. Root installation and firmware modification happen outside the app using exact-model documentation.

Can it tell me with certainty whether my phone is rootable?+

No app can honestly guarantee that from Android build fields alone. Trill Root reports conservative outcomes and explains their evidence. Carrier policy, region, exact model, firmware, rollback protection, and current project support still require verification.

Why does “unknown” not trigger older exploits?+

An unknown signal is missing evidence, not a vulnerability. Old one-click chains are often patched, device-specific, unmaintained, or redistributed with unacceptable risk. Trying them indiscriminately can compromise data or prevent boot.

What does the optional root check do?+

After an explicit confirmation, it runs the fixed command su -c id with a 20-second limit and bounded output. UID 0 confirms that an existing root manager granted access. Failure does not prove the device is unrooted.

Does it collect my IMEI, serial number, contacts, or location?+

No. Those values are outside the collector’s fixed allowlist. The app requests no runtime permissions and has no Internet permission. Exported reports can include a build fingerprint, so review them before sharing.

Is bootloader unlocking safe?+

It carries material risk. Unlocking normally erases data and can weaken physical security, affect warranty, break protected apps or updates, and expose permanent vendor flags. Never proceed without matching stock firmware and a tested recovery plan.
